# ЕППБ — Единый портал поддержки бизнеса

MVP цифровой платформы поддержки бизнеса Холдинга «Байтерек» на базе **универсального
no-code/low-code конструктора услуг**. Конкурсное решение (Astana Hub Hub Market).

Ключевая идея — не отдельная электронная услуга, а **платформа-конструктор**: услуга
описывается JSON-схемой, а один движок превращает её в конструктор, пошаговый клиентский
визард и автоматические расчёты. Новая услуга = новая запись, без разработки кода.

---

## Быстрый старт

### Вариант 1. Docker (для экспертной оценки)

Требуется только Docker.

```bash
docker compose up --build
```

Приложение поднимется на **http://localhost:8000** с PostgreSQL, автоматическими
миграциями и демо-данными.

### Вариант 2. Локально (Laravel Herd / PHP 8.4)

```bash
composer install
npm install
cp .env.example .env
php artisan key:generate
php artisan migrate --seed   # по умолчанию SQLite
npm run build                # или `npm run dev` для разработки
```

## Демо-сценарий

1. **Главная** — назначение портала, поиск, каталог направлений, статистика.
2. **AI-помощник** (`/assistant`) — описываете ситуацию словами → подбор мер поддержки.
3. **Каталог → карточка услуги** — переход к подаче.
4. **Пошаговый визард** (под демо-аккаунтом) — сложная услуга «Приобретение вагонов в
   лизинг» как понятный сценарий: ветвление, автоматические расчёты, проверка БИН,
   загрузка документов, отправка с номером заявки.
5. **Личный кабинет** — заявки, статусы, история, обзор данных.
6. **Конструктор** (под админ-аккаунтом, `/admin/services`) — создание/изменение услуги
   с живым предпросмотром и **AI-генерацией структуры из описания**.
7. **Модули** — карта проектов, аналитическая отчётность, полезные материалы.

## Архитектура

**Schema-driven ядро.** Услуга хранит JSON-схему (`services.schema`): этапы → поля →
условия показа → формулы расчёта → документы. Один формат питает три интерпретатора:

- **Конструктор** (`admin/services/builder`) — визуальный редактор схемы.
- **Клиентский визард** (`applications/wizard`) — рендер пошаговой формы.
- **Движок валидации/расчётов** (`app/Support/*`) — на сервере.

Клиентский движок (`resources/js/lib/schema-engine.ts`) зеркалит серверный
(`app/Support/FormulaEvaluator.php`, `ConditionEvaluator.php`, `ServiceSchema.php`) для
live-режима. Формулы вычисляются безопасно (shunting-yard, без `eval`); при отправке
сервер пересчитывает всё заново и не доверяет клиенту.

### Стек

- **Backend:** Laravel 13, PHP 8.4. БД: PostgreSQL (Docker) / SQLite (локально).
- **Frontend:** Inertia + React 19 + TypeScript, Tailwind v4, shadcn-компоненты.
- **Карта:** Leaflet + OpenStreetMap.
- **AI:** Claude (Anthropic Messages API).

## AI-компонент

Использует Claude при наличии ключа; без ключа работает детерминированный fallback
(демо-режим), поэтому подбор и генерация доступны всегда.

```dotenv
ANTHROPIC_API_KEY=sk-ant-...
ANTHROPIC_MODEL=claude-opus-4-8
```

Сценарии: подбор услуги по описанию ситуации (`AiService::suggestServices`) и генерация
черновика схемы услуги для автора (`AiService::generateServiceSchema`).
